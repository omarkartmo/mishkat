# دليل بنية التوزيع والتشغيل التجارية لنظام MISHKAT
## MISHKAT Commercial Distribution & Support Architecture Guide

---

## 1. نظرة عامة على بنية التوزيع الموحدة (Unified Installer)

تم تصميم بنية التوزيع لنظام **MISHKAT** لتعمل وفق فلسفة:
> **تثبيت واحد موحد ← تشغيل فوري بدون تبعيات خارجية ← مراقبة ذكية مركزية ← تحديث آمن دون فقدان للبيانات.**

لا يطلب النظام من العميل النهائي أو مسؤول المدرسة تثبيت Git أو Node.js أو خادم PostgreSQL منفصل أو Chrome، حيث تم تضمين بيئة التشغيل الكاملة وقاعدة البيانات المدمجة (`PGlite`) داخل المنتج.

---

## 2. أدوار التثبيت في حزمة التثبيت الموحدة (`MISHKAT-Setup.exe`)

عند تشغيل مثبت البرنامج `MISHKAT-Setup.exe` بصلاحيات المسؤول (Run as Administrator)، تظهر شاشة لاختيار دور الجهاز:

| الدور (Role) | المكونات المثبتة تلقائياً | ما لا يتم تثبيته على الجهاز |
|---|---|---|
| **MISHKAT Server** | <ul><li>خادم MISHKAT الإنتاجي المجمع (`dist/server.cjs`)</li><li>Runtime مدمج لـ Node.js (`bin/node.exe`)</li><li>قاعدة بيانات PostgreSQL مدمجة (`LibraryData/pgdata`)</li><li>خدمة ويندوز التلقائية (`MishkatLibraryService`) عبر NSSM</li><li>منظومة النسخ الاحتياطي (7 نسخ محلية + Drive)</li><li>وكيل الدعم والتشخيص (Support Agent)</li><li>المحدث الذكي (MISHKAT Updater)</li><li>فتح منفذ 3000 في جدار حماية ويندوز (Firewall Rule)</li><li>اختياري: تهيئة الدعم عن بُعد (Tailscale)</li><li>اختصارات سطح المكتب وقائمة Start للإدارة</li></ul> | <ul><li>أدوات التطوير (Git, GitHub, VS Code)</li><li>Node.js على مستوى نظام الويندوز (Global PATH)</li><li>خادم PostgreSQL مستقل</li><li>Antigravity أو أي حزم إضافية</li></ul> |
| **MISHKAT Student** | <ul><li>تطبيق الطالب المكتبي (`MISHKAT-Student.exe`) المبني بـ Tauri 2</li><li>التحقق التلقائي من توافر WebView2 وتثبيته إذا لزم</li><li>بيئة مطابقة ومغلقة خالية من أشرطة التصفح المفتوحة</li><li>طابور تخزين محلي غير متصل للأخطاء (Offline Queue)</li><li>درع حظر المواقع غير المعتمدة (Whitelist Guard)</li><li>أيقونة سطح المكتب وقائمة Start لتطبيق الطالب</li></ul> | <ul><li>Git أو مستودعات المصدر</li><li>Node.js أو NPM</li><li>خادم MISHKAT أو قاعدة البيانات المركزية</li><li>أي أدوات تطوير أو برامج تصفح خارجية</li><li>Tailscale أو أدوات الوصول عن بُعد</li></ul> |
| **Server + Student** | <ul><li>تثبيت كامل لجميع مكونات الخادم والخدمة الذاتية.</li><li>تثبيت تطبيق الطالب المكتبي على نفس الحاسوب مع ضبط الاتصال بـ `http://localhost:3000`.</li></ul> | — |

## 3. حماية بيانات المؤسسة أثناء التحديث والإصلاح (Data Preservation Invariants)

1. **المسار المحمي `LibraryData/`:**
   يحتوي على:
   - `pgdata/`: قاعدة بيانات المدرسة الكاملة.
   - `books/`: ملفات الكتب الرقمية، الأغلفة، والملحقات.
   - `backups/`: النسخ الاحتياطية المشفرة والمفتوحة.
   - `secrets/`: مفاتيح الربط وتوكنز Google Drive.
2. **قاعدة الأمان الذهبية:**
   - **يمنع منعاً باتاً** حذف أو استبدال مجلد `LibraryData` أو ملف `.env` أثناء عمل Install أو Upgrade أو Repair.
   - عند إلغاء التثبيت (`Uninstall.exe`)، يسأل البرنامج المستخدم صراحة: *"هل ترغب في الاحتفاظ بقاعدة البيانات والكتب والنسخ الاحتياطية؟"* ويوصي بالاحتفاظ بها.

## 4. بيئة الطالب المغلقة وحماية المواقع المعتمدة (Whitelist Guard)

1. **البيئة الآمنة (Controlled Kiosk Environment):**
   - لا توجد ألسنة متعددة (No multi-tabs).
   - لا يوجد شريط عناوين مفتوح (No URL address bar).
   - تعطيل أدوات المطورين (DevTools) وقائمة النقر الأيمن (Context Menu) في إصدارات الإنتاج.
   - شريط تحكم تربوي بسيط: **[ رجوع ] [ تقدم ] [ الرئيسية ] [ تحديث ]** مع زر **[ إبلاغ عن مشكلة ]**.
2. **فحص الروابط والمواقع المعتمدة:**
   - تخضع الروابط الخارجية لقائمة المواقع المعتمدة في قاعدة البيانات المركزية (`whitelisted_portals`).
   - عند محاولة الدخول إلى نطاق غير معتمد، يتم حظر التنقل فوراً وعرض شاشة مشكاة الواضحة:
     > **«هذا الموقع غير متاح ضمن المواقع المعتمدة في MISHKAT»**
   - يتم تسجيل محاولة الدخول غير المصرح بها كحدث تشخيصي تلقائي وإرساله إلى خادم المشرف.

## 5. نظام التقارير والتشخيص التلقائي (Student Telemetry & Aggregation)

### ما الذي يتم تسجيله تلقائياً؟
- انهيارات واجهة React (`React Error Boundary`).
- الأخطاء البرمجية غير المعالجة (`window.onerror` و `unhandledrejection`).
- أخطاء تحميل أو تصيير ملفات الكتب (`PDF_RENDER_FAILED`, `EPUB_RENDER_FAILED`).
- انقطاع الاتصال بالخادم المركزي وتجاوز مهلة الطلب (`SERVER_UNREACHABLE`).
- محاولات زيارة مواقع خارج القائمة المعتمدة (`UNAPPROVED_DOMAIN_BLOCKED`).
- بلاغات الطلاب اليدوية عبر نافذة "إبلاغ عن مشكلة".

### درع الخصوصية الصارم (Sanitization Guard):
قبل كتابة أي خطأ محلياً أو إرساله للخادم، يتم إخضاع النص لدالة `ClientEventSanitizer`:
- **ما يتم تنقيته وحذفه فوراً:** كلمات المرور، رموز JWT، التوكنز، الهواتف، الإيميلات، محتوى الكتب، وملاحظات الطلاب.
- **ما يتم إرساله فقط:** رمز الخطأ، مسار الشاشة، إصدار التطبيق، وصف تقني منقى، ومعرف الجهاز (`clientId`).

### طابور التخزين غير المتصل (Local Offline Queue):
- إذا انقطع اتصال حاسوب الطالب بالخادم، تُحفظ الأحداث في طابور محلي بحد أقصى **100 حدث** لمنع استهلاك مساحة القرص.
- يُعاد إرسال الأحداث تلقائياً فور عودة اتصال الشبكة، وتُحذف من الحاسوب فقط بعد استلام تأكيد الخادم (HTTP 200).

### التجميع الذكي للأخطاء (Error Aggregation):
بدلاً من عرض 50 سجلاً مكرراً لنفس المشكلة على 15 جهازاً:
يجمع الخادم الأخطاء المتطابقة في سجل موحد:
- **رمز الخطأ:** `PDF_RENDER_FAILED`
- **التكرار:** 30 مرة
- **الأجهزة المتأثرة:** 15 جهازاً (مع قائمة المعرفات `stu-lab-01`, `stu-lab-02`...)
- **أول رصد وآخر رصد**
- **أثر الشيفرة المنقى (Sanitized Stack Trace)**

## 6. وكيل الدعم الفني ولوحة التحكم (Support Agent & Dashboard)

داخل لوحة تحكم المشرف (Admin Sidebar)، يوجد تبويب:
**«صحة النظام والدعم الفني» (System Health & Support)**

يعرض 4 شاشات متكاملة:
1. **نظرة عامة على الخادم:**
   - حالة خدمة ويندوز (`MishkatLibraryService`).
   - استهلاك الذاكرة والمعالج ومدة التشغيل المستمرة (Uptime).
   - فحص استجابة قاعدة البيانات ومساحة القرص المتاحة.
   - حالة النسخ الاحتياطي السحابي عبر Google Drive والنسخ المحلي.
2. **الأخطاء المجمعة (Aggregated Errors):**
   - رصد المشاكل الشائعة مصنفة حسب الخطورة (حرجة، تنبيه، معلومات).
   - إمكانية فتح تفاصيل الخطأ ومعرفة أي حواسيب تعاني منه.
3. **أجهزة الطلاب المتصلة (Student Stations):**
   - قائمة بجميع الحواسيب المعتمدة في المدرسة.
   - مؤشر لحظي (متصل الآن / غير متصل).
   - رقم IP وإصدار التطبيق وعدد أخطاء اليوم لكل جهاز.
4. **المحدث التلقائي (Updater):**
   - فحص وجود تحديثات معتمدة للمنصة بنقرة واحدة.

## 7. نظام التحديث الآمن بدون توقف (MISHKAT Safe Updater)

يعمل المحدث وفق **بروتوكول الخطوات العشر الذاتية**:
1. جلب بيان الإصدار المعتمد (`manifest.json`) وفحص التوقيع الرقمي (SHA-256).
2. تنزيل حزمة التحديث إلى `LibraryData/temp/`.
3. **أخذ نسخة أمان احتياطية فورية وتلقائية لقاعدة البيانات** (`mishkat_pre_restore_...json`).
4. أخذ لقطة أمان لملفات التطبيق التنفيذية.
5. إيقاف خدمة ويندوز مؤقتاً (`net stop MishkatLibraryService`).
6. استبدال ملفات الشيفرة المجمعة فقط مع الإبقاء على `LibraryData/` و `.env`.
7. تشغيل ترحيلات الجداول الجديدة تلقائياً (`runMigrations`).
8. تشغيل خدمة ويندوز (`net start MishkatLibraryService`).
9. فحص صحة الخادم بعد التحديث عبر `/api/v1/health`.
10. **التراجع التلقائي (Rollback):** إذا فشل فحص الصحة خلال 30 ثانية، يستعيد النظام تلقائياً ملفات وقاعدة بيانات النسخة السابقة ويعيد تشغيل الخدمة مع تسجيل تقرير بالخلل.

## 8. كيفية بناء حزمة التثبيت `MISHKAT-Setup.exe`

1. **تجهيز ملفات الإنتاج:**
   ```powershell
   npm run build
   ```
2. **تشغيل سكربت البناء الآلي:**
   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\build-installer.ps1
   ```
3. **إذا لم يكن NSIS مثبتاً:**
   - حمّل وثبت [NSIS 3.x](https://nsis.sourceforge.io/Download).
   - شغّل:
     ```cmd
     makensis installer\mishkat-setup.nsi
     ```
   - سينتج المثبت الموحد جاهزاً للنشر:
     `c:\projects\mishkat\MISHKAT-Setup.exe`
